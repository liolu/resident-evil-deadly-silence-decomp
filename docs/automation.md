# Automation

Everything that does not need a human is scripted. A human (or an assistant) only writes C code; the tools build,
check, suggest drafts, brute-force near matches and publish.

Only the build tools are in this repo (\	ools/\: configure, ROM rebuild, \match.py\, \probe_compiler.py\).
The matching tools (\gametools/...\ below) live in [DS Decomp Studio](https://github.com/liolu/ds-decomp-studio)
and run from this folder: \python ../../studio/gametools/auto_match.py\ (or set \DSD_PROJECT\ to this folder).

| Tool | What it automates |
|---|---|
| `tools/moulinette.py` | The whole pipeline in one command (see below) |
| `tools/match.py` | Progress (`status`), worklist, single-function check, strict `verify`, README progress table |
| `gametools/auto_match.py` | Tries an m2c draft for every function not yet in a source file and adds the ones that already match to `src/auto/` |
| `gametools/draft.py` | C drafts generated by [m2c](https://github.com/matt-kempster/m2c) from the disassembly |
| `gametools/permute.py` | [decomp-permuter](https://github.com/simonlindholm/decomp-permuter): random rewrites of an almost-matching function until it matches |
| `tools/probe_compiler.py` | One function against every compiler version / flag set |
| objdiff (GUI) | Rebuilds and re-diffs automatically every time a source file is saved |

## The moulinette

```shell
python tools/moulinette.py                          # sync, build, drafts, verify, commit and push to main
python tools/moulinette.py --no-push                # commit locally only
python tools/moulinette.py --no-commit              # verify only
python tools/moulinette.py --permute func_0200cbdc --minutes 30
```

Steps:
1. `git pull --ff-only`
2. `configure.py` (first time) and `ninja`: extract, split, link and rebuild the ROM
3. `ninja dis`, then m2c drafts for every unmatched function of the delinked files → `build/drafts/<function>.c`
4. Automatic matching (`gametools/auto_match.py`, see below); `--permute-near N` also runs the permuter on N near misses
5. Optional permuter run on one function → `build/permuter/<function>/output-<score>-*/source.c`
6. `match.py verify`: byte-identical ROM, every `complete` file at 100%, ASCII-only sources
7. If the verification passed and something changed: README progress table, pre-commit hooks (then verify again if
   they reformatted code), commit listing the newly matched functions, `git push origin HEAD:main`

Nothing is committed or pushed when a check fails. Because publishing goes straight to `main`, the verification is
the only safety net: never bypass it.

## Automatic matching (`src/auto/`)

`gametools/auto_match.py` (step 4 of the moulinette) takes every ARM function of the main module that is not covered by
`delinks.txt`, generates an m2c draft, compiles it with the project's compiler and compares it with the game:

| Result | What happens |
|---|---|
| match | written to `src/auto/<function>.c`, declared `complete` in `delinks.txt` |
| near (same size, a few instructions differ) | kept in `build/auto/near/`: permuter candidates (`--permute-near N`) |
| size / compile | needs human work |

The first run matched **976 of 3,542 functions** (mostly small ones, about 4.7% of the code bytes) and kept 330 near
misses. After the additions, `match.py verify` must pass, otherwise every change of the run is rolled back.

Two corrections are applied to the drafts automatically:
- **Unused leading arguments.** m2c drops parameters the function never reads but names the others after their
  register (`arg1` = r1). The missing parameters are put back, otherwise the arguments land in the wrong registers.
- **Assembly-only instructions.** Straight-line functions using `swp`/`swpb`, `mrs`/`msr` or coprocessor
  instructions (never generated by the compiler) are written as CodeWarrior `asm` functions, between
  `// clang-format off` / `// clang-format on`. Drafts that still contain `M2C_ERROR` are rejected.

- **Byte offsets on unknown globals.** m2c writes `&data_X + (i * 16)` meaning bytes, but `data_X` is typed
  `M2C_UNK` (4 bytes) so C would scale the offset again. The addition is rewritten in bytes. In clean code these
  are arrays: `data_X[i].field`.

When a draft is close but not exact, `auto_match` also tries these rewrites one by one:
- **Returned value.** m2c types a function `void` when no caller uses its result, but the code keeps the stored
  value in `r0`: `return x = v;` / `return ++x;`.
- **Pointer + constant in bytes.** `arg1 + 8` on an `s32 *` means 8 bytes, not 8 elements.
- **Table at a fixed address.** `M2C_FIELD(((i * 4) + 0x027FF000), s32 *, 0xDA0)` is `((s32 *)0x027FFDA0)[i]`.

- **Forwarded arguments.** m2c declares callees without parameters (`func()`), so the compiler feels free to reuse
  `r0`-`r3`. When the game keeps them intact, the function passes its own first 1-4 arguments to the callee.

Drafts that do not compile get mechanical repairs first: old-style declarations for callees (`func();`),
`*(void *)addr` → `*(M2C_UNK *)addr`, and dereferences of variables m2c typed as integers. `include/m2c.h` also
defines `NULL`, whose absence alone blocked 512 drafts.

Every draft is tried with 2.0/sp1p5, then with 1.2/sp2p3 (see [compiler.md](compiler.md)); files that need 1.2 are
added to `config/usa/compilers.txt`.

With these rules later runs added 129, 40, 34, 15, then 129 (`NULL`), 7 (repairs) and 147 (compiler 1.2) functions
(1,500/3,608 in total).

Two more variants: fields of `volatile` structures (re-read after each access) and interrupt guards
(`state = OS_DisableIrq(); ...; OS_RestoreIrq(state);`), alone or combined. Profiles tried, in order: 2.0/sp1p5,
1.2/sp2p3, 1.2/sp2p3 `-proc arm7tdmi`. Later run: +12 (1,513/3,608).

`src/auto/` is raw m2c code: it is byte-exact but not clean (`s32`, `M2C_FIELD(...)`, `temp_r2`...). It uses the
types of `include/m2c.h`. Two rules:
- when a real source file (e.g. `StdGame.c`) is delinked over the same addresses, move the functions into it, clean
  them up and delete their `src/auto/` files and `delinks.txt` entries;
- renaming a function in `symbols.txt` also requires renaming it in the `src/auto/` files that call it.

Overnight run, permuter included:

```shell
python tools/moulinette.py --permute-near 100 --near-minutes 5
```

## Engine context for m2c

`include/engine.h` holds the engine types and the prototypes identified by hand (`fx32`, `VecFx32`,
`VEC_DotProduct`, the interrupt helpers...). `gametools/gen_context.py` (run by `auto_match.py`) adds the prototype of
every function already defined in `src/` to `include/m2c_protos.h`, and gives the preprocessed result to m2c with
`--context`. m2c then knows the real arguments and return values of the callees instead of guessing them.

- Drafts include `m2c_protos.h` after `#define M2C_SELF_<function>`, so a file never redeclares its own function.
- When the context makes m2c fail, the draft is regenerated without it (plain `m2c.h` types).
- Functions without a real prototype get a **guessed** one from `gametools/infer_signatures.py`: the argument count is
  the highest of `r0`-`r3` read before being written (up to the first call), and a value is returned if a caller
  reads `r0` right after the call. Types stay `M2C_UNK`. `gen_context.py --no-guess` leaves them out.
- Each draft is generated twice when needed, with and without the context, and the better result is kept: a wrong
  guess can make a call fail to compile.
- **Adding a correct prototype to `engine.h` improves every draft that calls the function**: it is the cheapest way
  to help the automation. First run with the context: +23 functions.

## Daily loop (human part)

1. Run the moulinette once: it refreshes drafts for the functions left to do.
2. Open objdiff on the project, pick a function, start from `build/drafts/<function>.c`.
3. Edit the C file in `src/`; objdiff rebuilds on save. Iterate until 100%.
4. Stuck at a few instructions? `python tools/moulinette.py --permute <function> --minutes 30` and come back later.
5. Run the moulinette again: it verifies and publishes.

## Installing the optional tools

m2c (GPL-3.0) and decomp-permuter are not shipped with this repository.

```shell
git clone https://github.com/matt-kempster/m2c
git clone https://github.com/simonlindholm/decomp-permuter
python -m pip install graphviz toml Levenshtein psutil
```

Point `M2C_PATH` and `PERMUTER_PATH` to the clones (defaults: `tools/m2c` and `tools/decomp-permuter`).
The permuter also needs `bash`, `gcc`, `arm-none-eabi-as` and `arm-none-eabi-objdump` in `PATH`.

> [!WARNING]
> On Windows, `bash` must be Git Bash, not `C:\Windows\System32\bash.exe` (WSL): put Git's `bin` directory first
> in `PATH`.

## Notes
- m2c output is a draft, not a solution: it ignores the original types and often uses temporaries
  (`temp_r2`). Clean it up following [engine.md](engine.md).
- The permuter score is a distance: 0 means a match. Copy the winning `source.c` back into the real file and check
  with objdiff; the permuter can produce unnatural code, so tidy it up while keeping the match.
- `permute.py` kills its worker processes with `psutil`, because `taskkill /T` relies on WMI, which is broken on
  some Windows installations.
